# Strategy audit — SiteSentry — 4 July 2026

Scope: every strategy document read against the working code, knowledge base, and pipeline
configuration. Ruff, mypy, and pytest run against the current backend. Advisory; written by an
automated session. Treat as a prompt for qualified review, not a final determination.

## Overall verdict

The project is strategically coherent but sequenced out of order. The deterministic reasoning core
— the stated moat — is genuinely built, tested, and working, which is the hardest conceptual part.
But the roadmap's first rule ("get the data model right first so later layers are additive, not
rewrites") has been broken: Milestone Zero is incomplete while Milestone One work is well under
way, and several fields the design says cannot be retrofitted are absent from the code. Nothing
built so far is wasted, but the next work must go backwards before it goes forwards.

## Gaps — ordered by severity

### 1. Multi-tenancy is absent from the code (non-negotiable violated)

FUNDAMENTALS: "Every record and storage location carries a tenant identity from the first line of
code." The `Finding` dataclass has no `tenant_id`, no `site_id`, no `inspection_id`, no
`section_id`. The `/consolidate` endpoint accepts findings with no tenant scoping. The whole
justification for this principle was that isolation is never retrofitted.

### 2. The "cannot be retrofitted" field list is unimplemented

DATA_MODEL.md closes with an explicit list of fields that must exist from the first stored audit.
None are present: no `recurrence_key` (kills future repeat-finding detection and historical
comparison), no priority `suggested`/`confirmed`/`adjusted` split (the human override is the most
valuable training signal and it is not being captured), no `due_date`/`closed_date`, no element
outcomes, no `status` lifecycle, no append-only `audit_log`. There is no persistence layer at all,
so nothing is a "stored audit" yet.

### 3. Milestone Zero tasks remain open while Milestone One is being built

The Data Protection Impact Assessment (`docs/DPIA.md`) has not been drafted — marked "required
before any real-site use". The data model has not been implemented as entities. The first
knowledge-base batch has not been adjudicated. No redaction stub, no free-text-handling rule in
code, no retention thinking.

### 4. The entire knowledge base is provisional; the adjudication loop has never run

Every provision, action, and mapping is marked PROVISIONAL; clause references were authored
shallow and never verified against the L25 publication. The pack README defines a human
adjudication loop (draft → qualified professional verifies against source → settled) and it has
completed zero cycles. There is an open flagged decision in the draft (whether Control of
Substances Hazardous to Health Regulations govern chemical eye-hazard findings) that nobody has
adjudicated.

### 5. The capture model does not exist

Template, sections, and prompted elements are designed in docs/ but unbuilt: no template JSON
in the pack, no element-outcome record, no positive-comment capture. Every performance measure
in Milestone Four is defined as an aggregation over element outcomes — no outcomes, no measures.

### 6. A design invariant is violated by the test harness

CAPTURE_INTERFACE.md: "the vocabulary the interface offers and the keys in the knowledge base
come from one source, so an auditor can never select a combination that has no entry." The harness
offers all tag × reason combinations including `hiviz × doesnt_fit` and `hand × doesnt_fit`, which
are deliberately unmapped. The invariant holds for the future production UI; the test harness
is a developer tool and the engine flags unmapped combinations correctly.

### 7. The continuous integration pipeline would fail today

`ruff format --check` would reformat 9 of 11 backend files — the CI job runs exactly that step.
`backend/api.py` imports FastAPI, which is not in `requirements.txt`; mypy in CI fails on the
unresolvable import. The CI installs only `requirements.txt`, not `api_requirements.txt`.

### 8. No frontend started

Milestone One explicitly includes Flutter screens. Nothing exists in `app/`. The browser harness
has none of the speed-first capture mechanics that CAPTURE_INTERFACE.md calls "a fixed
requirement, not a refinement."

### 9. Knowledge base breadth is one section of one hazard area

Coverage is protective equipment only (5 tags, 13 mappings). The CAPTURE_INTERFACE.md
prompted-element list names hearing and respiratory protection, which are absent from the
vocabulary. The sourcing map already names the next areas (L22, L24, L153) — none started.
Full text storage and version/effective dates for provisions are unbuilt; no record carries
the required Open Government Licence attribution line.

### 10. Smaller structural drifts

- Priority is not rule-computed. The band is a direct human pick with no severity/likelihood rule.
- Evidence records exist only as a `document_types` vocabulary stanza; the record type and
  management-documentation section are unbuilt.
- `infra/` does not exist; United Kingdom residency is asserted only in a placeholder workflow.
- No `pyproject.toml`; tool behaviour differs between machines.
- DEVELOPMENT.md "suggested first issues" still describes the old vision-first plan, contradicting
  the audit-first reorder that happened at Stage 7.

## Recommended action order

1. Implement Milestone Zero entity fields (cannot-retrofit: tenant_id, site_id, inspection_id,
   section_id, recurrence_key, priority triple, dates, status, audit_log) around the existing engine.
2. Draft `docs/DPIA.md` — required before any real-site use and cheap to do now.
3. Run the adjudication loop on the existing protective-equipment batch; settle the COSHH decision.
4. Fix the pipeline: ruff format, pyproject.toml, reconcile the two requirements files.
5. Build the template/prompted-element/outcome model so element outcomes are stored from day one.
6. Start the Flutter shell only after items 1 and 5, so screens bind to the real data model.

The strategy itself needs no revision — every gap is the code not yet honouring the documents,
not the documents being wrong.
